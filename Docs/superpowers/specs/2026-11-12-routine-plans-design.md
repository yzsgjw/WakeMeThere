# 通勤项目（Routine Plans）设计文档

日期：2026-11-12
状态：待批准

## 一句话

把「一次出行 + 站点队列」换成「几条日常通勤项目」：每个项目有名字、目的地、提醒半径、生效星期、生效时间段、铃声、震动、总开关；列表按开/关分成「进行中 / 未进行」，点开能改能存。

## 为什么

用户真实的用法是两条固定路线——工作日早上坐车到公司、晚上下班回家——而不是每次手动挑站点排队。站点队列要求用户每次出行前操作一遍，实际不会被用；通勤项目设置一次，之后只管开关。

## 目标

1. 项目列表：按 `isEnabled` 分「进行中 / 未进行」，行内直接开关，点击进编辑页。
2. 项目字段：名字、目的地（地图选点）、提醒半径、生效星期、生效时间段、铃声、震动、总开关。
3. 到站时除通知/铃声/语音外，提供**全屏到站画面**（可达性见「约束」）。
4. 地图选点时能用滑杆调**范围大小**，以直径表述，圆圈实时跟着变。
5. 撤掉界面上所有「站点队列 / 多站接力 / 开始·停止追踪」的入口。

## 非目标

- 不做到点自动弹出 App（系统不允许）。
- 不做多目的地接力（代码保留在 `TripRelayService`，界面不再暴露）。
- 不做云端同步、账号。
- 不做 App 内购买的铃声。

## 约束（决定实现方式的硬事实）

1. **iOS 没有「到 7:30 自动在后台开始追踪」**。能做到的是：项目一直挂着，但只在「星期匹配 + 时间窗内」才真正响应围栏。
2. **锁屏"不做任何操作就全屏盖屏"只有系统级能做**（来电/闹钟，或 Critical Alerts + 需 Apple 单独审批）。App 能做到的三条：
   - 通知点一下 → 直达全屏到站页（deep link）；
   - 锁屏 Live Activity 卡片上的按钮 → 直达全屏到站页；
   - App 正在前台/刚被唤醒时 → 直接 `fullScreenCover` 盖住。
3. 围栏上限 20 个、最小半径 100m（沿用既有约束）。
4. SwiftData 只能加带默认值的字段（轻量迁移），不能删已有字段。

## 方案选择

列表语义有两个走法：

- **A（已选）**：所有开着的项目同时算「进行中」，靠时间段分工，谁在窗口内谁生效。
- B：同一时刻只允许一条「进行中」，到点自动切换。否决理由：后台无法保证准点切换，会出现「以为在盯其实没盯」。

围栏注册策略：

- **A（已选）**：开着的项目一律注册围栏，触发时再判断星期与时间窗。代价是占围栏名额，好处是不依赖 App 在 7:30 醒着。
- B：只在窗口内注册。否决理由：窗口开始那一刻没有任何事件能唤醒 App 去补注册。

## 数据模型改动（`Reminder` 上加字段，全部带默认值）

| 字段 | 类型 | 默认 | 含义 |
|---|---|---|---|
| `weekdayMask` | Int | 62（周一~五） | 生效星期，bit0=周日 … bit6=周六 |
| `chimeName` | String | `classic` | 到站铃声（对应 `AlarmChime`） |
| `vibrationEnabled` | Bool | true | 到站震动 |
| `fullScreenOnArrival` | Bool | true | 到站是否允许全屏画面 |

沿用既有字段：`title`（项目名）、`placeName`/坐标（目的地）、`radius`、`startTime`/`endTime`（时间段）、`isEnabled`（开关）。

## 界面改动

### 1. 项目列表（替换现有「站点」tab）

```
项目
┌───────────────────────────────┐
│ 进行中                         │
│ ┌───────────────────────────┐ │
│ │ 上班               [开 ●] │ │
│ │ 公司 · 半径 300m           │ │
│ │ 周一~五 07:30–09:00        │ │
│ │ 🔔 标准   📳 震动开         │ │
│ └───────────────────────────┘ │
├───────────────────────────────┤
│ 未进行                         │
│ ┌───────────────────────────┐ │
│ │ 回家               [关 ○] │ │
│ │ 家 · 半径 500m             │ │
│ │ 周一~五 18:00–20:00        │ │
│ └───────────────────────────┘ │
└───────────────────────────────┘
        [+ 新建项目]
```

行内 Toggle 直接改 `isEnabled` 并重注册围栏；点击行进入编辑页；左滑删除。

### 2. 编辑页

按「这是个通勤项目」的顺序排：名字 → 目的地（地图选点）→ 提醒半径 → 生效星期 → 时间段 → 铃声（带试听）→ 震动 → 全屏到站 → 总开关 → 保存。

### 3. 地图选点加范围滑杆

底部卡片加一条滑杆，**以直径表述**（100 m – 4000 m），拖动时 `MapCircle` 实时缩放，旁边小字显示「直径 400 米 · 半径 200 米」。确认时把半径（直径÷2）写回项目。

### 4. 全屏到站页

大字站名 + 剩余距离 + 「我到了 / 稍后再提醒」两个按钮，背景随铃声状态显示「响铃中 / 播报中」。进入方式见「约束」第 2 条的三条路径。

## 行为细节

- 触发判定顺序：项目启用 → 星期匹配 → 时间窗内 → 到站复核（距离 + 精度）→ 响铃 + 语音 + 通知 + （可选）全屏。
- 时间窗跨零点（如 23:00–01:00）按「或」处理。
- 铃声与震动读项目自身字段，不再读全局开关。
- 全局设置里的「默认提醒距离」只影响新建项目的初始值。

## 风险

1. 一个都没真机验证过，这批改动同样只能靠 CI 编译 + 用户装机。
2. 项目多了会挤占 20 个围栏名额（每条项目 1 个）——到 20 条才需要处理，先记着。
3. 全屏页在锁屏场景依赖用户点通知，不是自动的，这一点已在上文写明，不做过度承诺。

## 我给自己的判断（不需要你回答）

- 「项目」直接用 `Reminder` 扩展，不新建模型 —— 省一次迁移，也让原有围栏/通知代码全部复用。
- 编辑页沿用现有 `ReminderEditSheet` 改造，不重写 —— 已有的地图选点、搜索、粘贴链接逻辑不动。
