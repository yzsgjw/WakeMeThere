## 二、候选方案 A：接入第三方 DesignFoundation 换皮

**主张**：不动业务，把 UI 换成 `NerdSnipe-Inc/design-foundation` 的 Liquid Glass 皮。

**结论：不采纳（至少现在不）。**

理由按重要性排序：

1. **它要接管的就是我们已经自己写完的那层。** 现在 `NearNoteStyle.swift` 是唯一真源，全 App（行程 / 地图 / 提醒 / 设置 / 编辑 / 引导 / 权限）都引用它，一套 token 换色换圆角。引一个第三方主题框架，等于把已经统一的东西重新拆开对齐。
2. **Liquid Glass 是 iOS 26 的观感。** 目标机是 iPhone 15 Pro Max / iOS 18.3.2，系统的玻璃材质 API 根本不存在，框架只能靠自绘伪造；伪造出来的玻璃在深色底 + 地图页面上很容易糊成一层雾，反而降低可读性（这是我在设计阶段就避开的：地图上只用 1px 边和 0.07 白透明度）。
3. **零第三方依赖是个资产。** 现在整个 App 只依赖系统框架（SwiftUI / MapKit / CoreLocation / ActivityKit / AVFoundation）。加 SwiftPM 依赖后：编译时间、ipa 体积、上游包是否继续维护、以及"企业证书重签平台会不会把 SwiftPM 产物一起处理"都变成新的不确定项。上次正是因为不想多一个 `App Group` 才把桌面小组件砍掉，衡量标准是一致的。
4. **它对我们最脆弱的地方毫无帮助。** 这个 App 真正难的是围栏误报、后台唤醒、静音穿透、多站接力游标持久化——都不是皮肤问题。

**什么条件下重新考虑**：换到 iOS 26 设备、且 Apple 官方 Liquid Glass API 稳定之后，优先直接用系统的 `.glassEffect` 之类，而不是引第三方包。

## 三、候选方案 B：工具箱主壳 + NearNote 作为子模块

**主张**：`WakeToolbox` 主 App + `NavigationSplitView` 侧边栏 + `Modules/NearNoteReminder`（业务包）/`NetTools`/`CodeTools`。

**结论：记为远期目标，不是现在。**

- 方向本身没问题，但**顺序错了**：现在连一次真机围栏触发都还没验证过。先把单个功能做扎实，再谈壳。
- 它的前置条件比看起来多：
  - 模块间共享数据要 `App Groups` → 需要付费开发者账号（免费签名 + 第三方重签都不稳）；
  - 多 Target + 多 Extension（Widget、通知扩展）→ 企业证书重签时每一个 `.appex` 都要同证书，失败面成倍放大；
  - 侧边栏在 iPhone 上是"临时抽屉"，对单功能 App 没有收益。
- 真正值得从 B 里先借的一点：**业务与导航解耦**。这个已经在做——`TripRelayService`、`LiveActivityService`、`AlarmPlaybackService`、`RouteETAService` 都是无 UI 的服务层，将来抽成 Swift Package 是机械操作，不需要现在就拆。

**触发条件**：付费账号到位 + 单站/多站真机全绿 + 确实有第二个工具要装进来。三者缺一不动。

## 四、我的路线（按"会不会翻车"排序，不按"好不好看"）

**P0 · 正确性（正在做）**
1. 到站复核闸门（本轮已做）：围栏事件带来的是缓存定位，用「实际距离 + 定位精度」二次确认，只在证据明确不足时否掉，宁可多响不漏站。
2. 定位质量可视化：行程页显示 `±N m`，弱信号时提示"提醒可能晚一点"。
3. 待补：进站后 30 秒内的重复触发抑制（冷却已有，但地铁进出站会来回穿圈）。

**P1 · 体验缺口**
4. 多铃声切换 UI（现在只有 `AlarmChime.wav` 一个）。
5. 行程分享/导出（`ShareLink` 现在只分享 App 本身）。
6. 站点拖拽排序。

**P2 · 生态**
7. Siri / 快捷指令（`AppIntent`，零第三方依赖，纯粹是工作量）。
8. 规则化外观（按时间/地点切换深浅配色）。

## 五、决策记录

| 日期 | 决策 | 原因 |
| --- | --- | --- |
| 2026-11 | 剥离 CloudKit + App Group，改纯本地 | 第三方重签会剥 entitlements，带 CloudKit 直接签不过 |
| 2026-11 | 砍桌面小组件、恢复仅含 Live Activity 的 Widget Extension | 灵动岛界面只能在扩展里画；桌面组件依赖 App Group 才能读数据 |
